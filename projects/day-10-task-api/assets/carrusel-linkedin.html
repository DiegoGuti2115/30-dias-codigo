01 · Problema y alcance

Gestionar tareas mediante una API local.

Un CRUD con un alcance intencionadamente pequeño: reglas claras, respuestas coherentes y sin infraestructura externa.

02 · Arquitectura

Responsabilidades separadas.

La capa HTTP no contiene las reglas de negocio: las rutas delegan en el servicio y este usa un repositorio local en memoria.

03 · Contrato y validaciones

La entrada se valida antes de llegar al dominio.

Los esquemas separan creación, reemplazo, actualización parcial, lectura y listado.

  "completed": true,

04 · Errores y decisiones

Casos límite con respuesta predecible.

La API traduce errores de dominio y conserva el formato estándar de validación cuando la solicitud no cumple el contrato.
