¿Qué pasa con un archivo antes de confiar en él?

Día 12: construí una API que inspecciona una carga y devuelve metadatos verificables, sin almacenarla.

Una sola carga por solicitud

Nombre, tamaño, tipo declarado, extensión y huella SHA-256.

El problema

Un archivo recibido no es una verdad.

Su nombre, extensión y tipo MIME vienen del cliente. Pueden orientar, pero no prueban qué contiene el archivo ni que sea seguro.

El riesgo de asumir demasiado

Usar el nombre como ruta, guardar bytes innecesariamente o presentar metadatos como validación de contenido.

!

La API no detecta malware ni identifica el formato real: esa limitación es intencional y explícita.

Contexto

La primera decisión fue reducir alcance.

Nada de almacenamiento, cuentas, colas, URLs remotas, análisis semántico ni Azure Blob en la versión 1.

Local y efímero

La carga se procesa durante la solicitud; no se persisten bytes, resultados ni metadatos.

Un límite concreto

Máximo 5 MiB de contenido para mantener un procesamiento acotado.

Un contrato claro

Solo existe POST /api/v1/inspect con un campo multipart llamado file.

La solución

Inspeccionar sin interpretar el archivo.

La API trata cada entrada como no confiable, valida el nombre y calcula una huella sobre los bytes originales.

1
Recibe multipartExactamente un archivo en file.
2
Valida el nombreSin separadores, traversal ni caracteres de control.
3
Lee por bloquesMide bytes y aplica el límite de 5 MiB.
4
Devuelve SHA-256Una huella determinista del contenido recibido.

Funcionalidades principales

Metadatos útiles, con límites honestos.

#SHA-256

Huella hexadecimal de 64 caracteres sobre los bytes exactos.

↧Extensión normalizada

Deriva el último sufijo y señala extensiones ambiguas.

MTipo declarado

Refleja el MIME de la parte multipart, si existe; no lo valida contra el contenido.

✓Errores uniformes

Respuestas seguras para multipart, tamaño, validación, método y fallos internos.

Los nombres con varios sufijos se informan como ambiguos; no se bloquean por ese único motivo.

Valor diferencial

Diseñada para no prometer más de lo que hace.

Separación de responsabilidades

FastAPI gestiona transporte; la inspección pura valida, limita y calcula la huella.

Seguridad observable

Los errores no exponen contenido, nombres de archivo, rutas del sistema, trazas ni detalles internos.

Comportamiento comprobado

Pruebas unitarias, HTTP y de entrega cubren límites, errores, determinismo y aislamiento entre solicitudes.
